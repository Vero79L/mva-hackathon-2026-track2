# MVA Track 2 — case-driven candidate triage engine

A disease-agnostic gate engine for N-of-1 rare-disease drug repurposing. It reads a
**case manifest** and a **gates config**, validates both, then applies the
directionality prerequisite followed by four patient constraint gates (oncology /
pediatric / renal / growth — three can reject, growth only flags). Unknown or malformed
inputs **BLOCK** — they never pass silently. Risk axes the gates structurally cannot see
are computed and printed rather than left implicit. Swap the case file to run another disease; no code change.

The engine demonstrates gate **logic**. The scientific judgment (eligibility and
research disposition per candidate, with citations) lives in the canonical candidate
table: `docs/candidates_canonical.json`, from which all views are generated by
`build_views.py` in this directory.

## No patient data here
This repository contains **no raw genomic or clinical files**. It does list rules-permitted DERIVED facts (two public variant coordinates already in ClinVar/competitor repos, HPO terms, mechanism analysis). Raw VCF/FASTQ/clinical files stay in a controlled local area under a 30-day post-close deletion obligation
(see `../DATA-LOCATION.md`). `.gitignore` excludes those file types as a secondary
barrier. The HF login automation is deliberately **not** in this package.

## Requirements
- Python >= 3.9, PyYAML 6.0.3 (pinned in `requirements.txt` / `pyproject.toml`).

`run.sh` uses `python3` unless you override it. If your default `python3` has no PyYAML,
either install it (`python3 -m pip install -r requirements.txt`) or point the script at an
interpreter that has it:

```sh
PYTHON=/path/to/python ./run.sh          # or: PYTHON=$(which python) ./run.sh
```

`run.sh` checks this before it does anything and tells you which of the two to do.

## One-command run (clean environment)
```sh
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
./run.sh                 # real case + synthetic case + selftest, writes outputs/
```
Or with uv (single-file inline deps): `uv run src/triage.py --case config/cases/bub1b_mva.yaml --candidates evidence/candidates_from_canonical.yaml`

## Building the submission PDF

```sh
sh make_pdf.sh          # -> docs/Vero7878_track2_report.pdf
```

Needs `pandoc` and a LaTeX install with `xelatex`. It is deliberately **not** part of `run.sh`:
`run.sh` must stay runnable in a clean Python-only environment, and a reviewer reproducing the
engine does not need a TeX toolchain. The script builds from a temporary copy of `docs/REPORT.md`
so the Markdown stays clean for GitHub, and gives the mechanism figure its own landscape page —
at portrait text width its node labels render around 6pt, which is unreadable.

## Tests
```sh
python3 src/triage.py --selftest     # 28 regression checks (input validation + gates + scenarios)
```
Expected: `ALL PASS`. The checks cover: wrong-direction rejects; unknown defect_direction or
age typo BLOCKs the case; out-of-range and wrong-type inputs BLOCK; a risk tag contradicting
its own safety assessment BLOCKs; a clean input can still reach STRONG; the scenario gate
rejects an invalid objective class, flags a conditional one, blocks an undeclared one, blocks
a malformed scenario block, and stays inert with no scenario; and five checks run against the
case's own constraint levels so the gates' reject / require / flag branches are exercised.

## Layout
```
src/triage.py                 validated gate engine (+ --selftest)
config/case.schema.yaml       case manifest schema (documentation)
config/scoring.yaml           directionality + G1-G4 hard gates (data)
config/cases/*.yaml           case manifests (real + synthetic)
evidence/candidates_from_canonical.yaml   engine fixture (GENERATED from the canonical table)
outputs/                      snapshot of the latest clean run (regenerated by run.sh)
```

## Scalability
Run on another disease by adding a `config/cases/<id>.yaml` with a new `defect_direction`
(and a matching rule in `config/scoring.yaml` if the direction is new). The synthetic
gain-of-function case shows the directionality rule flipping with the input. This
demonstrates that the gate logic is case-driven; it is **not** a cross-disease discovery
claim — candidate generation and evidence appraisal remain curated.

## Submission documents (docs/)
